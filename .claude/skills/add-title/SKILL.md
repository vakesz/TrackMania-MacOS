---
name: add-title
description: Checklist for adding a game title to the TrackMania Mac hub or changing an existing one's registry entry (config/titles/*.json), such as its installer URL or hash, prefix, app name, bundle ID, executables or save directories. Use it whenever a title JSON or assets/titles/ is touched, or the user asks to support another TrackMania (or similar) game, even if they only mention one field.
---

`config/titles/*.json` is the only source of title data. The shell reads it through `python -m trackmania_mac.hub.registry export`, and Swift only sees it through `trackmania-mac hub snapshot`. So a title change should be a data change, never a hard-coded path in shell or Swift.

1. **Entry.** Copy a similar title (e.g. `config/titles/tmu.json`) to `config/titles/<id>.json` and fill in its fields. `src/python/trackmania_mac/hub/registry.py` (`_FIELDS`) is the schema. It rejects unknown keys, so a misspelt field fails instead of being ignored.
   - `user_subdir` is the folder under UserData that the game reads (its `Nadeo.ini` `UserSubDir`). It must be one of `save_dirs`, so uninstall guards always cover it.
   - `needs_tmloader` is true for titles that Play starts through Competition Patch and CoreMod. It requires `game_exe` `TmForever.exe`, the only program ModLoader targets here. Other titles launch their own executable.
   - Do not add a prefix path. The prefix, saves, launcher and icon locations all derive from the title id (`games/<id>/prefix`, `saves/<id>`, `launchers/<id>`, `icons/<id>.icns` under `~/Library/TrackManiaMacOS`), so ids keep titles apart.
   - `bundle_id_game` and `bundle_id_settings` are required. By convention they are `local.trackmania-mac.<id>.game` and `local.trackmania-mac.<id>.settings` (Nations Forever, the first title, has `local.trackmania-mac.game` and `.settings`).
   - Leave `legacy_prefix_subdir`, `legacy_bundle_id_game` and `legacy_bundle_id_settings` out. They record where releases before the shared data folder kept an existing title and what they called its apps, and only the migration reads them. A new title has no earlier install.
   - The installer's `source_url`, `source_sha256` and `source_size` go here, not in `config/pins.json`, which holds only shared downloads.
   - Optional release pins, only when the exact build is known: `game_version` with `game_exe_sha256` (doctor then verifies the executable; the `online` installer kind requires them), and `creative_openal_sha256` (the Creative `OpenAL32.dll` the release ships, which install replaces with OpenAL Soft). Leave them out otherwise.
   - `source_interactive` (bool, optional; the registry leaves it None when absent) marks a pinned installer that needs a person to click through it. It requires installer kind `online`.
   - `source_patch` is `{header_sha256, edits: [{offset, before, after}], sha256_after}`: byte edits to the pinned Inno Setup's decompressed first header block, which install applies to a copy of the setup through `trackmania_mac.install.setup_patch` and runs instead of the download (see "Nations ESWC setup without a launch option" in `docs/runtime.md`). `offset` is lowercase hex like `0x3aed9`, `before` and `after` are lowercase hex bytes of the same length, and edits must not overlap. `header_sha256` is that block's hash before the edits and `sha256_after` the copy's hash, which must differ from `source_sha256`. The module reads only the Inno Setup 5.1 layout (`rDlPtS07` offset table, setup data 5.1.2) and refuses any other. Requires installer kind `online`. The shell does not receive the field; it only sees the `source-patch` component.
   - `updates` is a list of `{url, sha256, size}`: official Inno Setup updates, run silently in order after the base installer. https only; `size` is required. Requires installer kind `online`.
   - `overlay` is `{url, sha256, size, remove}`: a `.tar.gz` unpacked over the game folder after the updates, after which the plain file names in `remove` are deleted from it. https only; `size` is required. Requires installer kind `online`. No `remove` name may equal `game_exe`.
   - `nx_compat` is a non-empty list of plain file names in the game folder (no duplicates, case-insensitive) that install marks with the PE `NX_COMPAT` flag, after the overlay, through `trackmania_mac.install.pe_flags`. List a file when it lacks the flag: Wine then makes all memory executable, which is very slow under Rosetta (see `docs/runtime.md`). Requires installer kind `online`, and no name may be one the overlay `remove`s. When it lists `game_exe`, `game_exe_sha256` is the hash after the flag is set (or after `game_exe_patch`). The shell receives it as `TRACKMANIA_MAC_TITLE_NX_COMPAT`.
   - `game_exe_patch` is `{file, sha256_before}`: a patch for `game_exe` that install applies after the NX_COMPAT step, through `trackmania_mac.install.exe_patch` (see "Nations ESWC particle speed patch" in `docs/runtime.md`). `file` is `<id>/<name>.json` under `config/exe-patches`, which ships in the launcher payload; `sha256_before` is the executable's hash before the patch (after the NX_COMPAT flag when `nx_compat` lists it), and `game_exe_sha256` is the hash after it. Requires installer kind `online`. A patch file adds one code section and writes 5-byte jumps into it; it must hold only our own code and the bytes it replaces, never game code. Build it from source with a builder like `trackmania_mac.build.sse_particles_builder`, and give CI a `--check` for it. The shell does not receive the field; it only sees the `game-exe-patch` component.
   - `game_save_dirs` is a non-empty list of folder paths relative to the game folder (`/`-separated, no `..`, none equal to or inside another, ignoring case) where the game writes saves instead of Windows Documents, such as `GameData/Profiles`. Each is kept in the saves folder at `<user_subdir>/<path>` and linked from the game folder by `trackmania_mac.install.game_saves`, so an uninstall that keeps saves keeps them (see "Saves in the game folder" in `docs/runtime.md`). No path may lie under `game_exe`, `launcher_exe`, an `nx_compat` file or a file the overlay removes. List only folders the game creates or fills itself: confirm with `innoextract -l` on the installer and each update, and `tar -tzf` on the overlay, that nothing they ship lies under a listed path, because shipped files there would move to the saves folder and the overlay refuses to write through a link. The shell does not receive the list; it only sees the `game-saves` component.
   - `game_system_config` is `{format, file}`: a default settings file install writes into the game folder after the NX_COMPAT step when none exists, through `trackmania_mac.install.system_config` (see "Nations ESWC settings" in `docs/runtime.md`). `format` must be one of `SYSTEM_CONFIG_FORMATS` in `registry.py` (today only `text-2006`, the text GBX Nations ESWC reads); a new format needs a generator in `system_config.GENERATORS`, checked against settings the game accepted. `file` is a plain file name that no installer ships and that is not `game_exe`, `launcher_exe`, an `nx_compat` file or a file the overlay removes. Requires installer kind `online`. The shell does not receive it; it only sees the `game-system-config` component. The file must never carry per-install or account data.
   - The basenames of `source_url`, every update URL and the overlay URL must be distinct, because they share `cache/games/<id>/`.
   - A download from outside the vendor (an archive.org mirror, a community build) is trusted only through its pinned hash. Say so in `docs/download-links.md`.
   - New titles start with `status` unsupported (listed, not expected to run yet). Move one to provisional once it installs, and to supported only once it is qualified; today `tmnf` and `tmu` are supported.
   - `link_url` and `link_label` are optional and go together: a related page (https only, label one line of at most 60 characters) that the hub shows under the notes, such as Trackmania 2020's separate macOS port. Set them in the JSON; never special-case a title in Swift.
   - `release_date` is required: the title's first release as `YYYY-MM-DD`, checked as a real date. The registry and the hub list titles oldest first by it (ties by id), so never reorder titles any other way.
   - Don't add `prefix_marker` or `needs_directx`. The marker is derived from the id, and every title gets DirectX.
2. **Components are derived, not configured.** `Title.components` decides the optional install steps, and the shell asks `title_has`:
   - `competition-patch` comes from `needs_tmloader`;
   - `openal` comes from `creative_openal_sha256`;
   - `source-patch` comes from `source_patch`;
   - `updates` comes from a non-empty `updates` list;
   - `overlay` comes from `overlay`;
   - `nx-compat` comes from a non-empty `nx_compat` list;
   - `game-exe-patch` comes from `game_exe_patch`;
   - `game-saves` comes from a non-empty `game_save_dirs` list;
   - `game-system-config` comes from `game_system_config`;
   - `system-config` (seeding the runtime's Forever-format `Default.SystemConfig.Gbx` into `user_subdir`) comes from `game_exe` `TmForever.exe`.

   Never branch on a title id in shell or Python. `tests/test_titles.py::TitleConditionalTests` fails on `TRACKMANIA_MAC_TITLE = ...`, `title.id == ...` and similar checks outside the legacy shims it lists. Add a registry fact or a component instead.
3. **Icon.** Add `assets/titles/<id>.svg`. The PNGs are generated and gitignored, and `tests/test_title_assets.py` fails without the SVG.
4. **New installer kind (only if no existing `installer` value fits):**
   - Update `INSTALLERS`/`ONLINE_INSTALLERS` in `src/python/trackmania_mac/hub/registry.py` and the label in `src/python/trackmania_mac/hub/snapshot.py`.
   - Add the install flow in `src/shell/lib/install/game.sh` and `src/shell/lib/commands/import.sh`.
5. **Docs and inventory.** Update the title table in `docs/hub-app.md`, "Which games work?" in `README.md`, the hard-coded games list in `website/index.html`, the game dropdown in `.github/ISSUE_TEMPLATE/bug_report.yml`, and the title id set in `tests/test_titles.py::test_allTitle_json_valid` (the one deliberate inventory).
6. **Verify.** Run `uv run --frozen --group test pytest -q tests/test_titles.py tests/test_title_assets.py tests/test_hub_backend.py`, then `make check`. `test_titles.py` checks that the shell's computed paths, components and exported values match the registry for every title, which catches a missing `TRACKMANIA_MAC_TITLE` or a hard-coded path.
